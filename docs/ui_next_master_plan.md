# KasaneCore UI刷新 全体計画書 (ui_next)

作成日: 2026-07-19
ステータス: 承認済み方針 / 実装中

## 1. 目的

KasaneCore の UI/UX を「モダンでスタイリッシュ、使いやすさ最優先」に刷新する。
既存機能(Lumen / Atlas / Echo / Nexus / Forge / Portal / Twin / 設定 / プロジェクト管理)は完全に維持する。

## 2. 現状分析(前提となる事実)

| 項目 | 実測値 |
|---|---|
| UI原本 | `ui.html` (888KB) — 起動時に `scripts/start_codeagent.py` が `ui/index.html` へコピー |
| インラインJSコア | 1ブロック約680KB(モード切替・チャット・プロジェクト・設定・Echo等の心臓部) |
| HTMLマークアップ | 約183KB、ユニークID 約700個 |
| 外部JSモジュール | `web/js/` 16ファイル 約660KB(atlas_claude_panel / atlas_dashboard / forge / portal / nexus 等) |
| CSS | `web/css/app.css` 134KB — **CSS変数駆動**(38トークン、`var(--…)` 755箇所) |
| 構造契約テスト | **68ファイル**が `ui.html` のDOM構造を、**75ファイル**が `web/js` を固定 |
| 配信 | FastAPI: `/` → `ui/index.html`、`/ui/` → StaticFiles(ui)、`/static/` → StaticFiles(web) |

## 3. 戦略決定: 「別UIをゼロから」ではなく「別UIとしてシェル+デザイン全面刷新、ロジック層は資産再利用」

### 検討した選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A. フルスクラッチ新UI | 全JS/HTML/CSSを書き直し | ❌ 1.3MBのJSロジックと300+エンドポイント連携の再実装。機能欠落・回帰が必至 |
| B. 既存UIの漸進改修 | ui.html を直接改修 | ❌ ユーザーが避けたい方式。契約テスト68本と衝突しながらの改修は高コスト |
| **C. 新UI(ui_next)= 新シェル + 新デザインシステム + ロジック層再利用** | 別ディレクトリに新UIを構築。DOM ID契約を保った本体マークアップを変換移植し、シェル(ナビ/ヘッダ/レイアウト)とCSSを全面刷新 | ✅ 採用。見た目・操作性は完全刷新、機能はJS資産ごと維持。レガシーは無傷で共存 |

### 採用理由

- 既存JS(インラインコア+16モジュール)は**IDベースでDOMに結合**しており、IDを保存すれば新しいレイアウト構造・新しいスタイルの中でもそのまま動作する。
- `app.css` がCSS変数駆動のため、**トークン層の一新+シェルCSSの新設+コンポーネント再スキン**で、全サーフェスの見た目を一貫して刷新できる。
- レガシー(`ui.html` / `web/`)には一切手を入れないため、**契約テスト68+75本はそのまま全部パス**し、いつでも切り戻せる。

## 4. 新UIの構成

```
ui_next/
  index.html        # 生成+手動洗練。新シェル(サイドバーナビ)+移植された本体マークアップ
  css/
    tokens.css      # 新デザイントークン(色/フォント/radius/影/モーション)
    app.css         # app.cssフォーク(トークン参照はそのまま新トークンを拾う)
    next.css        # 新シェル+コンポーネント再スキン(最後に読み込み、上書き層)
  js/
    core.js         # ui.htmlのインラインJSを抽出したコア(シェル関連のみ最小パッチ)
scripts/
  build_ui_next.py  # ui.html → ui_next 変換スクリプト(再実行可能)
```

- 外部JSモジュールは従来どおり `/static/js/*.js` を参照(共有・無改変)。
- 変換スクリプトにより、レガシーUIに将来変更が入っても新UIへ追従再生成できる。

## 5. デザイン方針(UX最優先)

- **ナビゲーション刷新**: ヘッダの小さなモードボタン群 → 左サイドバー(アイコン+ラベル、現在地が明確、ツールチップ付き)。モバイルは下部タブを再スタイル。
- **デザイントークン一新**: ネオングリーン(#00ff88)基調 → 深いスレート背景+バイオレット/シアン系アクセント。radius拡大、ソフトシャドウ、控えめなガラス効果。
- **タイポグラフィ**: Syne → Space Grotesk(見出し)+ Inter(UI本文)+ JetBrains Mono(コード)。
- **情報密度の整理**: 余白・行間の拡大、カード化、階層の明確化。既存の高密度パネルは崩さずスキンのみ刷新。
- **アクセシビリティ**: フォーカスリング、prefers-reduced-motion 対応、コントラスト確保。

## 6. 切り替え戦略(3フェーズ)

### Phase 1 — 共存(実装中)
- `/ui-next/` に新UIをマウント(StaticFiles)。`/` は従来どおりレガシー。
- 新旧を同時に開いて比較検証できる。

### Phase 2 — 検証
- ライブサーバー(:8000)で全6モード+設定+プロジェクト操作を実測検証。
- `scripts/smoke_ui_modes_playwright.py` を参考にした新UI向けスモーク(`scripts/smoke_ui_next_playwright.py`)で自動検証。
- 既存テストスイート(契約テスト含む)が全てパスすることを確認(レガシー無改変なので原理的にパスする)。

### Phase 3 — 完全切替
- `/` のデフォルトを新UIに変更。
- 環境変数 `KASANE_UI_VARIANT=legacy` で旧UIへ即時フォールバック可能(`/ui/` は常にレガシー、`/ui-next/` は常に新UI)。
- `ui.html` と `web/` は契約テストとフォールバックのため削除しない。

### 切り戻し手順(ロールバック)
1. `KASANE_UI_VARIANT=legacy` を設定してサーバー再起動、または
2. main.py の `root()` のデフォルト分岐を戻す1行修正。

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| コアJSがシェルDOM構造(header等)に依存 | core.js 抽出後にシェル参照箇所を洗い出し、新シェルでID互換を保つ。必要箇所のみcore.jsを最小パッチ |
| 新CSSの上書き漏れで一部画面が崩れる | app.cssフォークを土台にするため「漏れ=旧スタイルのまま表示」であり機能は壊れない。検証フェーズで順次上書き |
| 契約テストとの衝突 | レガシーに一切触れないため衝突しない。新UI固有のスモークを別途追加 |
| CDNフォント/marked依存 | レガシーと同一の依存のみ使用(オフライン時の劣化挙動も従来と同等) |

## 8. 検証完了の定義 (Definition of Done)

1. 6モード(Lumen/Atlas/Echo/Nexus/Forge/Portal)すべてが新UIで表示・操作できる
2. 設定モーダル、プロジェクト切替、TTS/ASRトグルが動作する
3. Playwrightスモーク(新UI)がグリーン
4. 既存pytestスイートがグリーン(レガシー契約含む)
5. `/` が新UIを返し、`/ui/` でレガシーに到達できる
